# CRM Lead Bot — версия для Vercel (webhook)

Та же логика, что и локальная версия (Telegram → квалификация заявки →
сделка в amoCRM), но переписана под serverless: вместо того чтобы бот сам
постоянно "спрашивал" Telegram про новые сообщения (polling), теперь
Telegram сам стучится к нам, когда что-то происходит (webhook). Это то,
что умеет бесплатно держать Vercel.

## Что изменилось технически (коротко, для понимания)
- `api/webhook.py` — это функция, которую Vercel запускает при каждом
  входящем сообщении. Раньше был один долгоживущий процесс, теперь —
  много коротких вызовов.
- Между вызовами обычная память не сохраняется, поэтому шаги диалога
  (имя → телефон → заявка) теперь хранятся не в памяти Python, а в
  **Redis** (бесплатная база от Upstash, подключается через Vercel).

## Пошаговая инструкция деплоя

### Шаг 1 — залить код в GitHub
Раз аккаунт GitHub у тебя уже есть:
1. Создай новый пустой репозиторий, например `crm-lead-bot`
2. В папке проекта (там, где лежит этот README):
   ```bash
   git init
   git add .
   git commit -m "initial"
   git branch -M main
   git remote add origin https://github.com/ТВОЙ_НИК/crm-lead-bot.git
   git push -u origin main
   ```

### Шаг 2 — создать проект в Vercel
1. Зайди на vercel.com/dashboard → **Add New → Project**
2. Выбери репозиторий `crm-lead-bot`, который только что запушил
3. Framework Preset можно оставить "Other" — Vercel сам увидит папку
   `api/` и поймёт, что это Python-функции
4. Пока не нажимай Deploy — сначала следующий шаг

### Шаг 3 — подключить Redis (Upstash)
1. В настройках проекта (или сразу после создания) открой вкладку
   **Storage**
2. **Create Database → Upstash → Redis** (может называться просто "KV" —
   это одно и то же по сути, работает через тот же протокол)
3. После создания Vercel сам добавит нужные переменные окружения в
   проект — но название переменной с URL подключения может отличаться
   (`REDIS_URL`, `KV_URL` и т.п.). Открой вкладку **.env.local** или
   **Quickstart** внутри созданной базы и посмотри точное имя переменной
   с адресом вида `rediss://...` — если оно не `REDIS_URL`, добавь ещё
   одну переменную окружения `REDIS_URL` с тем же значением вручную в
   Settings → Environment Variables проекта.

### Шаг 4 — добавить остальные переменные окружения
В Settings → Environment Variables проекта добавь:

| Имя | Значение |
|---|---|
| `BOT_TOKEN` | токен от @BotFather |
| `AMOCRM_SUBDOMAIN` | `prostozapaska` |
| `AMOCRM_ACCESS_TOKEN` | твой долгосрочный токен amoCRM |
| `WEBHOOK_SECRET` | придумай любую случайную строку, например `a8f3k29fjs` |

### Шаг 5 — задеплоить
Нажми **Deploy**. Через минуту-две получишь адрес вида
`https://crm-lead-bot-xxxx.vercel.app`.

Проверь, что функция жива — открой в браузере:
`https://твой-адрес.vercel.app/api/webhook`
Должно показать текст "Webhook жив...".

### Шаг 6 — сказать Telegram слать сообщения на этот адрес
Это единственный шаг, который делается не на Vercel, а у тебя локально,
один раз:

```bash
cd crm_lead_bot_vercel
export BOT_TOKEN="токен_от_botfather"
export VERCEL_URL="https://твой-адрес.vercel.app"
export WEBHOOK_SECRET="та_же_строка_что_в_шаге_4"
python scripts/set_webhook.py
```

Скрипт выведет ответ Telegram — там должно быть `"ok": true`. Дальше он
покажет текущую информацию о вебхуке — проверь, что `url` совпадает с
твоим адресом.

### Шаг 7 — проверка
Напиши боту `/start` в Telegram, пройди сценарий — сделка должна
появиться в amoCRM, как и при локальном тесте.

## Если что-то не работает
- **Бот не отвечает вообще** — зайди в Vercel → проект → Deployments →
  открой последний деплой → вкладка **Logs** — там будут видны ошибки
  выполнения функции в реальном времени.
- **`REDIS_URL не задан`** — значит переменная окружения называется
  иначе, см. Шаг 3.
- **Timeout при обращении к amoCRM** — на Vercel free tier лимит
  выполнения функции короче, чем при локальном запуске (обычно до 10 сек
  на Hobby-плане, увеличено в `vercel.json` до 30, но free tier может
  всё равно резать раньше — если видишь ошибку по времени в логах,
  напиши, разберёмся отдельно, это решаемо).
